# Task Manager API Documentation

A RESTful API for managing tasks, built with Go and Gin. Tasks are stored in memory, so data resets when the server restarts.

**Interactive docs (Postman):** <PASTE YOUR PUBLIC POSTMAN LINK HERE>

## Getting started

### Prerequisites

- Go 1.21 or newer (check with `go version`)

### Run the API

```bash
cd task_manager
go mod tidy
go run main.go
```

The server starts on `http://localhost:8080`.

### Test the API

- **Postman:** import the collection from the link below and set `base_url` to `http://localhost:8080`.
  `https://documenter.getpostman.com/view/57227945/2sBYHUULJ5`
- **curl** (on Windows PowerShell use `curl.exe`):

```bash
curl.exe http://localhost:8080/tasks
```

## Task object

| Field       | Type   | Description                           |
| ----------- | ------ | ------------------------------------- |
| id          | string | Unique ID, generated by the server    |
| title       | string | Required                              |
| description | string | Optional                              |
| due_date    | string | RFC 3339, e.g. `2026-10-30T17:00:00Z` |
| status      | string | `pending`, `in_progress` or `done`    |

## Error format

All errors return:

```json
{ "error": "message" }
```

## Endpoints

### 1. Get all tasks

`GET /tasks`

**Request body:** none

**Response:** `200 OK`

```json
[
  {
    "id": "1",
    "title": "Write report",
    "description": "Finish the weekly report",
    "due_date": "2026-10-30T17:00:00Z",
    "status": "pending"
  }
]
```

| Status | Meaning                              |
| ------ | ------------------------------------ |
| 200    | Tasks returned (empty array if none) |

---

### 2. Get a task by ID

`GET /tasks/:id`

**Request body:** none

**Response:** `200 OK`

```json
{
  "id": "1",
  "title": "Write report",
  "description": "Finish the weekly report",
  "due_date": "2026-10-30T17:00:00Z",
  "status": "pending"
}
```

| Status | Meaning                                       |
| ------ | --------------------------------------------- |
| 200    | Task found                                    |
| 404    | Task not found: `{"error": "task not found"}` |

---

### 3. Create a task

`POST /tasks`

**Request body:**

```json
{
  "title": "Write report",
  "description": "Finish the weekly report",
  "due_date": "2026-10-30T17:00:00Z",
  "status": "pending"
}
```

**Response:** `201 Created`, the created task with its `id`.

| Status | Meaning                                                        |
| ------ | -------------------------------------------------------------- |
| 201    | Task created                                                   |
| 400    | Invalid input (missing title, bad due date, or invalid status) |

---

### 4. Update a task

`PUT /tasks/:id`

**Request body:**

```json
{
  "title": "Write report (final)",
  "description": "Send to manager",
  "due_date": "2026-11-02T09:00:00Z",
  "status": "in_progress"
}
```

**Response:** `200 OK`, the updated task.

| Status | Meaning        |
| ------ | -------------- |
| 200    | Task updated   |
| 400    | Invalid input  |
| 404    | Task not found |

---

### 5. Delete a task

`DELETE /tasks/:id`

**Request body:** none

**Response:** `200 {"message":"task removed"}`

| Status | Meaning        |
| ------ | -------------- |
| 200    | Task deleted   |
| 404    | Task not found |

## Validation rules

- `title` is required and cannot be empty.
- `due_date` must be a valid RFC 3339 date-time.
- `status` must be one of `pending`, `in_progress`, `done`.
